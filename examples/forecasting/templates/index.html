Natural Gas Consumption Forecasting Interactive Lab

About this Lab

This application visualizes the pipeline for forecasting natural gas consumption in Prague. The goal is to predict consumption for the next 24 hours based on past data and weather conditions. The model uses a "Difference from Midnight" strategy to remove the daily baseline trend and focus on fluctuations.

Understanding the Algorithms
The "Best Fit Line"

Concept: Linear Regression assumes the relationship between the past (features) and the future (target) is a straight line (or flat plane).

In Forecasting: It calculates a weighted sum of inputs.
Prediction = w1 * (Yesterday's Consumption) + w2 * (Temperature) + Bias

Pros: Fast, interpretable.
Cons: Fails if the pattern is curved or complex (non-linear).

The "Committee of Trees"

Concept: It builds many "Decision Trees". Each tree asks a series of Yes/No questions (e.g., "Is Temp < 5°C?"). The final prediction is the average of all trees.

In Forecasting: It can learn complex rules like "If it's Monday AND Winter, consumption spikes". It captures non-linear patterns well.

Pros: High accuracy, handles complex patterns.
Cons: Can't predict values outside the range it saw during training.

ARIMA (AutoRegressive Integrated Moving Average)

A classical statistical method that predicts future values based entirely on the "inertia" and history of the series itself.

Uses past values to predict the future. It is essentially a linear regression of the data on itself.

yt = c + φ1yt-1 + ... + φpyt-p + εt
Logic: "The temperature today depends on a weighted sum of the temperature yesterday and the day before."
Parameter (p): The number of lag observations included in the model.

Differencing the raw data to make it "Stationary" (constant mean and variance).

y't = yt - yt-1
Logic: Instead of predicting the absolute value (e.g., stock price), we predict the change (price went up by $2).
Parameter (d): The number of times the data have had past values subtracted.

Uses past forecast errors (residuals) in a regression-like model.

yt = c + εt + θ1εt-1 + ... + θqεt-q
Logic: "If I predicted too high yesterday (negative error), I subtract a portion of that error from today's forecast to correct it."
Parameter (q): The size of the moving average window (lagged errors).

Understanding Evaluation Metrics
Definitions
  • MAE (Mean Absolute Error):
    The average magnitude of errors. It treats all errors equally.
    Formula: sum(|Actual - Predicted|) / N
  • RMSE (Root Mean Squared Error):
    Similar to MAE, but errors are squared first. This means large errors are penalized more heavily. If you have one very bad prediction, RMSE will skyrocket while MAE might stay low.
    Formula: sqrt(sum((Actual - Predicted)^2) / N)
  • R² (Coefficient of Determination):
    A score from -infinity to 1.0.
    • 1.0: Perfect prediction.
    • 0.0: Model is just as good as always predicting the average value.
    • Negative: Model is worse than just guessing the average.
Visualizing Residuals (Errors)

The red lines represent the Error (Residual) for each point. MAE is the average length of these lines. RMSE is based on the squared length.

Preprocessing Pipeline:
  • Data Cleaning: Missing values are handled, and the year 2019 is dropped.
  • Target Transformation ("Diff from Midnight"): Instead of predicting raw consumption, we predict the change from the last midnight value. This makes the series more stationary and easier for trees to learn.
  • Temporal Split: Training on 2013-2017, Testing on 2018 (No random shuffling to prevent data leakage).
  • Feature Engineering:
    • Cyclical Encoding: Hour (0-23) and Month (1-12) are converted to Sin/Cos pairs.
      Why? In a linear representation, hour 23 and hour 0 are far apart (difference of 23). In reality, they are next to each other. By mapping time to a unit circle using Sin/Cos, we preserve this relationship (23:00 is geometrically close to 00:00), helping the model understand the cycle of the day/year.
    • Lag Features: Past values (t-24h, t-48h, etc.) are added as columns.
    • Domain Features: Weekend flags and "Heating Season" indicators based on month.
